# トラブルシューティング

FlexAgent が返す `ErrorCode` ごとの、よくある原因・確認方法・復旧手順をまとめる。
UI のエラーバナー「Details」からは、このページの対応するアンカーへ遷移できる。

エラーには次の情報が付く（UI / CLI ともに同じ形）。

- **code**: 機械可読な `ErrorCode`（i18n キーも兼ねる）
- **message**: 英語のフォールバックメッセージ（UI は `code` を優先して翻訳する）
- **details**: 展開表示用の技術情報（パス、終了コード、HTTP status など）
- **retryable**: 同じ操作をそのまま再試行してよいか
- **recovery**: 復旧操作の候補（再試行 / ノード再接続 / 履歴 Replay で再開など）
- **data_safety**: 入力・ワークスペースがどうなったか（未変更 / 未送信 / 復元可能 / 消失）
- **request_id**: ハブログと突き合わせるための相関 ID

`request_id` はレスポンスヘッダ `x-request-id` と、ハブの `http_request` スパンにも入る。
まずはこれをキーにログを検索する。ノード側のログは `fxg logs`、ハブ側は `fxg logs hub`、
または `~/.flexagent/logs/` を確認する。

## エラー処理の規約（開発者向け）

1. `Result` を暗黙に捨てない。`mise run lint:errors` が
   `let _ =` / `map_err(|_|)` / `Result::ok` / `Result::unwrap_or_default` を禁止する。
   意図的に無視する場合は `fxg_protocol::discard_with!` に理由を書く。
2. ユーザーに影響する失敗は、ログだけでなく状態（`StatusChanged(Error)` / エラー応答）として表面化する。
3. バックグラウンドタスクは `spawn_logged!`（`Result` を返す）または
   `spawn_guarded!`（`()` を返す）を使い、panic と `Err` を必ず記録する。
4. 新しい `ErrorCode` を追加したら、同じコミットで
   `ui/messages/en.json` の `error_<code>` と、このファイルの `## CODE` を追加する
   （`cargo test -p fxg-protocol` の契約テストが検査する）。

---

## UNAUTHORIZED

- **原因**: トークンが無い・失効した・別の接続先のトークンを使っている。
- **確認**: `~/.flexagent/auth_token` と、URL の `?token=` / Cookie `fxg_session`。
- **復旧**: 接続メニューからトークンを入れ直す。接続先でトークンを再生成した場合は
  すべてのクライアントで再ログインが必要。

## FORBIDDEN

- **原因**: 認証は通ったが、操作が許可されていない（読み取り専用ノードなど）。
- **確認**: `details` の操作名とノード設定。
- **復旧**: 権限のあるノード / ハブで操作する。

## NODE_OFFLINE

- **原因**: 対象ノードがハブに接続していない、または一時 VM が停止した。
- **確認**: `GET /api/v1/nodes` の `is_online`、`fxg node status`。
- **復旧**: ノードを起動して再接続する。常駐ノードなら `fxg node start`、一時 VM なら再作成する。
  UI の「Reconnect」「Choose another node」を使える。

## ALREADY_RESOLVED

- **原因**: 同じ承認 / 質問に二度応答した（別タブ・再送）。
- **確認**: 応答済みかどうか。エラーにはならないのが正常。
- **復旧**: 何もしなくてよい。表示を更新する。

## BUSY

- **原因**: セッションが実行中で、その操作を受け付けられない。
- **確認**: セッションの `status` が `running` / `waiting_*`。
- **復旧**: ターン完了を待つ、またはキャンセルしてから再試行する。入力は送信されていない。

## INVALID_STATE

- **原因**: 前提条件を満たしていない（未リンクのプロジェクト、Git 外のパスなど）。
- **確認**: `details` のパス / セッション状態。
- **復旧**: メッセージに従ってプロジェクトのリンク、パス、ブランチを修正する。

## FORK_UNSUPPORTED

- **原因**: 使用中のエージェントが ACP ネイティブの `session/fork` +
  `session/load` に対応していない。fxg は履歴 Replay による Fork を行わない。
- **確認**: Web UI の Fork ボタンは対応エージェントでのみ表示される。CLI では
  `fxg session fork` のエラー詳細を確認する。
- **復旧**: Fork を使わずに新しいセッションを開始する。同じ会話を続けたい場合は
  同一セッション内でプロンプトを送る。

## RESUME_REQUIRED

- **原因**: 停止中のセッションで、エージェントがネイティブ復元（`session/resume` /
  `session/load`）に対応していない。履歴 Replay による明示的な再開が必要。
- **確認**: `details` / `params` の `session_id`。
- **復旧**: 「Resume with history」で再開してから送信する。ワークスペースは変更されていない。

## PTY_DISABLED

- **原因**: ノードのセキュリティ設定でリモート PTY が無効。
- **確認**: ノードの `allow_remote_pty` 設定。
- **復旧**: ローカル端末で操作するか、設定を変更してノードを再起動する。

## COMMAND_DUPLICATE

- **原因**: 同じ `command_id` のコマンドが既に処理された（冪等再送）。
- **確認**: 初回の結果が既に反映されているか。
- **復旧**: 何もしなくてよい。結果を再取得する。

## NOT_FOUND

- **原因**: セッション / プロジェクト / ノード / 承認リクエストが見つからない。
- **確認**: 対象 ID と、接続しているハブ / ノードが正しいか。
- **復旧**: 一覧を更新する。削除済みなら作り直す。

## INTERNAL

- **原因**: 想定外のハブ / ノード内部エラー。
- **確認**: `request_id` でログを検索し、`details` を確認する。
- **復旧**: 再試行する。繰り返す場合は `fxg support bundle` を添えて報告する。

## CONFIG_INVALID

- **原因**: `~/.flexagent/config.toml` が不正。
- **確認**: エラーのパスと行。`fxg doctor` で検査する。
- **復旧**: 設定を修正する。

## AGENT_NOT_INSTALLED

- **原因**: 指定エージェントがノードに入っていない。
- **確認**: `GET /api/v1/agents` の `installed`。
- **復旧**: 設定 → エージェントからインストールする（`npx` / `uvx` 実行も可）。

## AGENT_LAUNCH_FAILED

- **原因**: エージェントの起動コマンドが解決できない、またはプロセスが即終了した。
- **確認**: `details` のコマンド / 終了コード、ノードの PATH。
- **復旧**: コマンドのパス・実行権限を確認する。必要なら別ノードを選ぶ。

## AGENT_PROTOCOL_ERROR

- **原因**: ACP のハンドシェイク / メッセージが不正、またはバージョン非対応。
- **確認**: エージェントのバージョンと、ノードのログにある stderr。
- **復旧**: エージェントを更新 / 再インストールする。

## AUTH_REQUIRED

- **原因**: エージェントが認証を要求している（初回ログイン、トークン失効など）。
- **確認**: エラーの `details.methods` に認証方法（agent / terminal）が入る。
- **復旧**: `fxg agents login <agent>` を実行する。表示された方法を選び、
  terminal の場合はブラウザでログインしてコードを貼り付ける。ログアウトは
  `fxg agents logout <agent>`（エージェントが対応している場合）。

## GIT_UNAVAILABLE

- **原因**: `git` が見つからない、またはリポジトリでない。
- **確認**: `git --version` と対象パス。
- **復旧**: Git を導入する、リポジトリ内のパスを指定する。

## GIT_FAILED

- **原因**: worktree 作成・bundle 作成などの Git 操作が失敗した。
- **確認**: `details` の Git 出力。
- **復旧**: ブランチ名の重複、未コミット変更、権限を確認して再試行する。

## WORKTREE_CONFLICT

- **原因**: 既存 worktree とブランチ / パスが競合している。
- **確認**: `GET /api/v1/projects/:id/worktrees`。
- **復旧**: 既存 worktree を開く、別ブランチ名にする、または既存を削除する。

## SYNC_BACKLOG

- **原因**: ハブへの Outbox 同期が遅延 / 失敗している。
- **確認**: `system/info` の `unsynced_event_count`、ハブへの接続状態。
- **復旧**: 接続を復旧すると自動再送される。ローカルのイベントは失われない。

## DB_CORRUPT

- **原因**: DB の JSON / 列挙値 / `node_seq` が壊れている。
- **確認**: エラーの `details`、`node.db` / `hub.db` の整合性。
- **復旧**: バックアップから復元する。`fxg doctor` で検査できる。

## PROVISIONER_FAILED

- **原因**: 一時 VM の起動・プロビジョニング・ハンドシェイクに失敗した。
- **確認**: プロビジョナーのテスト実行とログ。
- **復旧**: プロビジョナー設定（認証・イメージ・ネットワーク）を修正して再試行する。

## VERSION_MISMATCH

- **原因**: ノード / ハブ / DB スキーマのバージョンが互換でない。
- **確認**: `GET /api/v1/system/info` の `version` とノードのバージョン。
- **復旧**: 同じバージョンに更新する。ハブを先に更新し、ノードを順次更新する。

## TIMEOUT

- **原因**: ノードからの応答が期限を超えた（エージェント起動が遅い、ネットワーク断）。
- **確認**: ノードの稼働状況と負荷。
- **復旧**: 再試行する。繰り返す場合はノードのログを確認する。

## DISK_FULL

- **原因**: ディスク容量不足（DB / ログ / スナップショット / ワークスペース）。
- **確認**: `df -h` と `~/.flexagent` の使用量。
- **復旧**: 空き容量を確保してから再試行する。

## PERMISSION_DENIED

- **原因**: ファイル / ソケット / 実行ファイルへの権限不足。
- **確認**: `details` のパスと所有者・パーミッション。
- **復旧**: 権限を修正する。必要なら別のユーザー / パスで実行する。

## IO_ERROR

- **原因**: ファイル読み書き・ソケット・パイプの I/O エラー。
- **確認**: `details` のパスと OS エラー。
- **復旧**: パスの存在・権限・空き容量を確認して再試行する。

## PTY_FAILED

- **原因**: PTY の作成 / 読み書き / 子プロセス管理に失敗した。
- **確認**: ノードのログ、対象シェルが存在するか。
- **復旧**: 端末を開き直す。リモート PTY が無効ならローカル端末を使う。

## HUB_ERROR

- **原因**: ハブ内部の処理失敗（DB / 集約 / 配信など）。
- **確認**: `request_id` でハブログを検索する。
- **復旧**: 再試行する。繰り返す場合は `fxg support bundle` を添えて報告する。

## CANCELLED

- **原因**: ユーザー操作またはシャットダウンで処理が中断された。
- **確認**: 意図したキャンセルかどうか。
- **復旧**: 必要なら再実行する。入力は保持されている。

## REVISION_MISMATCH

- **原因**: 設定の `expected_revision` が保存済みの revision と一致しない（別の画面が先に更新した）。
- **確認**: 設定カタログを再読み込みし、最新の値を確認する。
- **復旧**: 最新値を確認してから同じ変更を保存し直す。

## SECRET_MISSING

- **原因**: エージェントの `env_secrets` や Git 認証が参照する秘密ファイルが存在しない。
- **確認**: 設定画面の Secrets タブで「Missing」と表示されていないか確認する。
- **復旧**: 同じ ID の秘密を再登録するか、参照元の `env_secrets` を削除する。

## SECRET_IN_USE

- **原因**: カスタムエージェントや Git 認証設定から参照されている秘密を削除しようとした。
- **確認**: 一覧の `used_by`（参照元）を確認する。
- **復旧**: 参照元を変更・削除してから秘密を削除する。

## SECRET_INVALID

- **原因**: 秘密 ID が `[a-zA-Z0-9._-]{1,64}` に反する、値が空、またはシステム管理の秘密を変更しようとした。
- **確認**: ID と値を見直す。
- **復旧**: 正しい ID で保存し直す。
