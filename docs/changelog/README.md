# Changelog（設計判断・移行の記録）

後から参照する価値のある変更だけを月別ディレクトリ（`YYYY-MM/`）に記録します。
変更の一次情報は Git 履歴とコミットメッセージです。

## 記載基準

- **記録するもの**（いずれかに該当する場合）:
  - DB マイグレーション、またはプロトコル / API の型・互換性を変える変更
  - 複数クレートに跨がる構造変更、新しい抽象化・クレートの導入
  - 後から参照する設計判断・不変条件・トレードオフ（ステート docs に書くほどでないもの）
- **記録しないもの**:
  - 単一画面・単一コンポーネントの UI 調整（レイアウト・配色・文言・i18n・コピー）
  - 単発のバグ修正、リファクタ・リネーム、依存・ツールチェイン・CI の更新
  - 既存挙動の小さな改善
- **1 機能 = 1 ファイル**。コミットごとに増やさない。判断に迷う場合は作成しない。
- 複数フェーズに跨がる大規模な計画・設計提案は [`docs/proposals/`](../proposals/README.md) に作成してください。
