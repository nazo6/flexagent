# タイムラインのイベント部キャッシュ

- **日付**: 2026-11-26
- **対象パッケージ**: `ui`, `docs`
- **対象スクリプト**: `mise run fmt`, `pnpm --dir ui run check`, `pnpm --dir ui run test`

---

## 概要

ストリーミングのチャンクを受けるたびに、`buildTimelineItems` が全イベントを走査して
全会話アイテムを作り直していた。長いセッションではチャンクごとに全メッセージの
オブジェクトが新しくなり、Markdown の再レンダリングも広範囲に及んでいた。

## 変更

### `ui`

- `buildTimelineItems` を「確定イベント由来のアイテム列」と「ストリーミング差分の
  オーバーレイ」に分割した。
- 確定部分は `events` の配列・件数・先頭 / 末尾 `node_seq` をキーにキャッシュし、
  イベントが増減したときだけ再構築する。差分の受信ではキャッシュしたアイテム配列を
  浅くコピーして末尾にストリーミング項目を足すため、既存アイテムの参照が変わらない。
- 端末出力の差分はオーバーレイ側でアイテムを差し替えるので、キャッシュには波及しない。
- キャッシュの挙動（差分中の参照維持、イベント追加時の再構築、端末出力の非漏洩）を
  `reducer.test.ts` に追加した。
