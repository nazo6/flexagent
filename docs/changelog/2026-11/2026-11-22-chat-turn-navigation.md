# チャットのターンレールとターン目次

- **日付**: 2026-11-22
- **対象パッケージ**: `ui`
- **対象スクリプト**: `pnpm --dir ui run check`, `pnpm --dir ui run lint`,
  `pnpm --dir ui run test`, `mise run fmt:check`

---

## 概要

会話が長くなると、少し前の発言へ戻るのに延々とスクロールするしかなかった。
ツール実行や思考は `ActivityBlock` で 1 行に畳まれるため、スクロールバーの
つまみだけでは「どこに何があるか」も分からない。

タイムライン右端に常時表示する **ターンレール** と、ヘッダーから開く
**ターン目次** を追加した。どちらも同じ「ターン」索引を使う。

## ターンの定義 (`ui/src/lib/chat-turns.ts`)

- ターンは `user` イベントで区切り、次の `user` までのイベント
  （回答・ツール実行・承認・通知）をまとめる。
- 生のイベントを単位にしない。畳まれた作業が地図を埋めてしまうため。
- 各行は最初の空でない行をタイトルにし、連続する空白を畳む。
- `permission` / `elicitation` が未解決なら承認待ち・質問待ち、`notice` の
  `warning` / `error` はエラーとして記録する。解決済みの承認は数えない。
- 最初の `user` より前のイベント（ページングで途中から読んだ履歴や
  provisioning ログ）はどのターンにも属さない。

## ターンレール (`TurnRail.svelte`)

- チャット列の右端、スクロールバーの外側に置く。モバイルでは右端 6px に寄せる。
- 帯の位置と高さは **DOM の実測値**（`data-turn-seq` を付けたユーザー発言）に
  比例させる。Markdown・コードブロック・折りたたみで高さが変わるため、文字数
  では代用できない。等間隔のティックにするとクリック位置と本文がずれる。
- 帯は「ユーザー発言（太い）＋回答・作業（細い）」の 2 層。未解決の承認・
  質問・エラー通知は点で重ねる（`data-attention`）。
- 現在の表示範囲を枠で示し、クリック／ドラッグでスクラブする。ホバーで
  ターン番号と発言の先頭行を出す。
- 古い履歴が未読み込みのときは上端に「さらに上へ」のシェブロンを出す。ここを押すと
  追加読み込みだけを行う（全体の目盛りを偽装しない）。
- 計測は `ResizeObserver` + `rAF`。スクロール時は枠と現在ターンだけを更新し、
  アンカーの再計測はしない。ストリーミング中は内容の伸びで再計測される。
- `role="slider"` として ↑↓ / Home / End でターンを移動できる。

## ターン目次 (`TurnOutline.svelte`)

- ヘッダーの Turns ボタンで開く。本文に**重ねる**オーバーレイで、幅は取らない
  （`lg` 以上ではワークスペースドックと右側の幅を争うため）。外側クリックと
  Escape で閉じる。
- 1 行 = 連番 + 発言の先頭行（2 行まで）+ 要対応バッジ + ツール数。
- レールが算出した現在ターンを `activeSeq` として受け取り、スクロールに追従して
  ハイライトする。選択中の行が見切れていればリストを追従スクロールさせる。

## ページング・追従との整合

- ジャンプはアンカーの `getBoundingClientRect` から `scrollTop` を計算して
  `scrollTo` する。最新ターンへ飛ぶときだけ `followOutput` を維持し、それ以外は
  追従を止める。
- 追加読み込み（`loadOlder`）は既存の「読み込み前の高さを保つ」処理のままで、
  ターン数が変わることでレールが再計測する。
