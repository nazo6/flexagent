# サイドバーの未読インジケータ（端末ローカル）と実行中表示の整理

- **日付**: 2026-11-14
- **対象パッケージ**: `ui`, `docs`
- **対象スクリプト / 設定**: `pnpm --dir ui run check`, `pnpm --dir ui run lint`,
  `pnpm --dir ui run test`, `pnpm --dir ui run build`, `mise run fmt:check`
- **関連ドキュメント**:
  - [`docs/07-web-ui-and-pwa.md`](../../07-web-ui-and-pwa.md) §3.2

## 背景

サイドバーのセッション行は、ノードがオンラインであれば常に緑のドットを表示していた。
このドットはノードの可用性しか表さず、`idle` と `running` の区別には使えなかった。
また、別画面にいる間にエージェントの応答が完了しても、セッションを開き直すまで
新しい出力があったことを知る手段がなかった。

## 変更

- **実行中インジケータ**:
  - `running` のセッション行に signal 色の回転インジケータを表示し、`idle` と区別する。
- **ノード可用性ドット**:
  - 正常な（利用可能な）ノードでは緑ドットを表示しない。
  - 切断・オフライン・停止など利用できない場合のみ、従来の状態色ドットを表示する。
- **未読インジケータ**:
  - セッションを開いていない間に完了した `agent_message`（`is_complete = true`）を
    受信すると、そのセッションに signal 色の未読ドットを表示する。
  - セッションを開くと既読になり、開いている間のイベントは既読として扱う。
  - 既読位置はセッションごとの `node_seq` で管理し、`localStorage`
    (`fxg.session_read`) に保存する。
  - 初回のセッション一覧取得時、この端末で記録のないセッションは現在の
    `last_node_seq` を既読として初期化する（履歴全体が未読にならないようにする）。
  - セッション削除時は既読位置と未読状態を破棄する。
- **テスト**:
  - `ui/src/lib/stores/sync.test.ts` に未読化・既読化・再生済みイベントの
    スキップを検証するテストを追加。

## 設計判断

未読状態は**端末ローカルの表示状態**とし、ノード / ハブの DB・API は変更しない。
複数ブラウザ / 複数端末で既読状態を共有する場合は、ユーザー（またはトークン）単位の
`last_read_node_seq` をサーバー側に持つ API と DB 変更が必要になる。

## 不変条件

- 未読・既読は端末ローカルにのみ存在し、ノード / ハブへ同期しない。
- 未読になるのは完了したエージェントメッセージだけ（承認待ち・エラーは既存の
  Needs attention 表示で扱う）。
